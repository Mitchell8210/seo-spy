# Post-investigation AI interpretation

Dashboard Run Investigation and Website/Social Media Run Report now explicitly collect reports, save their immutable evidence, calculate the existing deterministic scores, then ask Muse Spark 1.3 for up to four prioritized recommendations. The model can synthesize actions beyond the coded findings. Every accepted action cites existing observations; linking an original finding requires at least one citation from that finding, while allowing additional measured context. Model text never changes scores or authorizes external writes.

The frontend uses the existing persistent local browser session and CSRF proof to POST `/api/wordpress/businesses/:businessId/investigations/overall|website|social` with `{confirmed:true}` (social also supplies `pageId`). This uses the existing local account setup and business/site binding; no server credential enters browser code. The old report endpoints remain collection-only. Dashboard interprets the final report pair once; nested channel collections do not each generate another interpretation. Terminal status is published after AI completes or fails.

Facebook's original OAuth cookie is scoped to `/api/facebook`. Successful local progress reads validate that credential and mirror its opaque session identifier into an HttpOnly, SameSite=Lax cookie scoped to `/api/wordpress`, so AI starts can use an existing login without asking for consent again. New OAuth callbacks also issue this companion cookie. Original credential/data-access expiry and revocation remain authoritative; disconnect clears both paths. An HTTP cookie-jar regression covers the cross-path handoff rather than manually attaching cookies.

Results live separately in application SQLite in `investigation_interpretations`, pinned to report hashes and the exact provider request. Reads through `/api/wordpress/local/businesses/:businessId/investigation-interpretation?reportIds=...` never generate, collect or retry. Pending and failed requests are retained and never automatically redispatched. Failed AI leaves the collected reports and score snapshots available with a partial outcome. Existing recommendation slots display validated AI text; no visible sections or styling were added. Newly synthesized actions without a finding appear in Dashboard's existing next steps, without inventing audit findings or executable targets.

Authenticated calls use the existing shared cumulative $25 ledger, atomic reservations and conservative provider accounting. This specific explicit operation can dispatch through the scoped provider while legacy generic interpretation remains mock-first. Output is capped at 1,500 tokens, reasoning is minimal, and no tools, automatic retries or external edits are enabled.
